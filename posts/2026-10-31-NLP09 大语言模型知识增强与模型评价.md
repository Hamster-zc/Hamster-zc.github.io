# 09 大语言模型知识增强与模型评价

## 1. 知识表示

### 1.1 经典知识表示方法

- 一阶谓词逻辑
- 产生式规则
- 框架理论
- 语义网络

### 1.2 RDF：主语、谓语、宾语

RDF 是用三元组描述资源的数据模型。

~~~text
(课程:NLP, 由教师讲授, 教师:杨老师)
(课程:NLP, 学分, 3)
~~~

按 RDF 1.1，主语可以是 IRI（Internationalized Resource Identifier，国际化资源标识符，用来在全局范围内标识一个资源的字符串，可以理解为给实体或关系起的一个全球通用的名字）或空白节点；谓语是 IRI；宾语可以是 IRI、空白节点或字面量。在 RDF 中，IRI 与普通字符串字面量属于不同类型的项。不同 IRI 也可能指向同一资源。

RDF 数据可以表示为有向标记图，其中主语和宾语构成节点，谓语标记有向边；宾语节点也可以是表示数值、字符串等数据的字面量。上面的三元组是概念示意，并非完整的 RDF 序列化语法。

“北京”这个字符串可以出现在城市名、机构名、书名中。若只存字符串而没有实体 ID，就难以判断两条三元组能否连接。

### 1.3 RDFS 与 OWL

RDFS 增加类、子类、属性等语义，例如：

~~~text
(猫, subClassOf, 哺乳动物)
(哺乳动物, subClassOf, 动物)
(咪咪, type, 猫)
~~~

据此可推导咪咪属于哺乳动物和动物。

OWL 提供比 RDFS 更丰富的本体表达能力，包括类的交、互斥、等价及属性限制；其中 OWL 2 DL 具有基于描述逻辑的形式语义。如果“猫”和“狗”被声明为互斥类，同一个个体又被断言同时属于两者，本体就会不一致。OWL 通常采用开放世界假设：未记录的事实不等于假，因此这些语义约束不能直接当作数据库的完整性校验规则。

RDFS 扩展了 RDF 的词汇，可描述类与属性的层次结构等语义。

### 1.4 知识图谱

知识图谱描述为实体、概念及关系构成的可计算模型。一个图谱通常不只存边，还要说明实体类型、关系语义、来源与有效时间。

Neo4j 常用属性图：节点和边可以带属性。RDF 则以三元组为基本数据模型。

例如关系“就职于”带有开始和结束时间，若只存“某人—就职于—某校”，就难以区分旧任职和现任职；多条任职关系本身不一定构成逻辑冲突。可把任职作为事件节点，再连接人物、机构和时间。

知识图谱构建过程

- 知识定义
- 知识抽取
- 知识补全
- 知识存储

## 2. 非结构化知识抽取

### 2.1 命名实体识别 NER（Named Entity Recognition）

目的是识别文本中实体提及的边界并判定类型，包括人名、组织机构名、地理位置等；部分标注体系也包含时间、日期等表达。NER 本身通常不负责把提及映射到知识库中的唯一实体，这属于实体链接任务。

| 基于   | 描述                                               | 优缺点                                                   |
| ---- | ------------------------------------------------ | ----------------------------------------------------- |
| 规则   | 基于规则的方法依赖于手工编撰的规则集、命名实体库等。                       | **优点**是可解释性强，能精确匹配特定模式；**缺点**是依赖人工构建规则，适应性差，难以覆盖复杂场景。 |
| 统计学习 | 基于统计学习的方法通常会先将实体识别转换为序列标注问题，然后运用统计机器学习模型来实现实体识别。 | **优点**是能够利用标注数据训练模型，适应性较强；**缺点**是特征工程依赖人工设计，泛化能力受限。   |
| 深度学习 | 在基于深度学习的方法中，模型可以自动学习文本中的特征表示用于实体识别。              | **优点**是能自动学习特征，可利用预训练表示；**缺点**是计算成本通常较高，跨领域泛化仍受数据与训练设置影响，预训练可降低任务标注数据需求。 |

### 2.2 关系抽取

目标是对实体之间的语义关系自动识别或抽取，以形成知识三元组。

可以在实体抽取的基础上进行，也可以和实体抽取联合进行。

### 2.3 远程监督

经典远程监督方法的标注假设是：若知识库中实体对具有某种关系，则把同时包含这两个实体的句子当作该关系的训练证据。

以使用 Freebase 的经典方法为例，训练时先识别实体提及，再将其与知识库实体匹配。若实体对在 Freebase 中存在某种关系，就以该关系构造监督标签，从共现句中提取特征，并按实体对汇总，用于训练关系分类器。Freebase 是该方法使用的知识库实例，不是远程监督必须使用的知识库。

在关系预测中：

1. 识别实体提及，构造候选实体对。
2. 从包含实体对的句子中抽取并汇总特征。
3. 使用训练好的分类器预测关系；实际系统还需处理“无目标关系”的情况，不能假定任意共现实体对都有目标关系。

因此远程监督的优点是低成本规模化，代价是标签噪声。

### 2.4 事件抽取

“事件类型”定义发生了什么，“触发词”在文本中指示事件，“论元角色”说明参与者的功能。同一实体可以在不同事件中扮演不同角色。

闭域事件抽取按预定义 schema 找字段；开域抽取不预先限定全部事件结构，但通常更难统一、消歧和评价。事件抽取结果要保留否定、条件、时间和来源。

## 3. 结构化与半结构化来源

关系数据库已经有表结构，抽取主要解决主键到实体 ID、外键到边、列到属性的映射。

ETL、CSV 导入、查询转 Cypher 等是常见实现途径。

半结构化来源如带有标签或栏目的网页、部分电子病历，有一定结构但不完全统一。电子病历也可能同时包含结构化字段和非结构化自由文本。网页可先用 DOM 或模板解析，再做内容抽取。

格式稳定时，规则可能更便宜、更易审查；格式频繁变化时，可以采用学习方法，但仍需把原始片段与抽取结果对应起来，便于追溯错误。

## 4. 知识增强的大语言模型

### 4.1 定义

知识增强的大语言模型（Knowledge-Augmented Large Language Model，KALLM）通过在训练或推理阶段引入知识资源，旨在改善知识密集型任务的表现、知识更新能力或证据可追溯性。收益取决于知识质量与融合方式，并不保证同时提升准确率、效率和可解释性；外部检索还可能增加延迟与成本。

工作原理：在模型训练或推理阶段将知识融入

- 知识内化：在预训练、继续预训练或微调等参数更新过程中，从知识与数据中学习，将知识编码进模型参数。
- 知识外用：在推理过程中，通过检索或工具调用等方式使用外部知识，为输出提供依据，但仍需检查检索质量与生成结果。

### 4.2 知识增强的模型预训练

- 语义知识：一种做法是利用语料中的连接词等线索，自动构造句间关系标签，再隐藏线索并训练模型预测关系。这更适合称为自监督或弱监督学习；连接词提供的是带噪声的关系线索，并不保证构成严格的逻辑蕴含。

- 人工知识库：例如 WordNet 用同义词集表示词义，并以语义关系连接这些词义；预训练时可设计知识预测目标或融合知识表示。构建词汇知识网络本身不等于完成模型训练。

- 融合世界知识的预训练：部分世界知识可表示为知识图谱。某些方法将三元组与相关文本对齐，设计联合掩码或其他联合训练目标，使模型学习文本与知识之间的联系；这是一类实现方式，并非所有知识增强模型的统一流程。

### 4.3 知识增强的模型推理

内容规划：主要涉及需求理解、知识检索和选择等

- 检索增强：通过检索系统从外部信息源获取与问题相关的材料，并将其作为生成的上下文。系统可以固定执行检索，也可以先判断是否需要检索。
- 思维链推理（CoT）：生成中间推理步骤以帮助处理复杂问题。CoT 本身不要求访问外部知识库，但可以与检索、工具调用结合。
- 上下文学习（ICL）：通过提示中的指令、示例等让模型在当前上下文中适应任务，通常不更新模型参数。

内容生成：模型结合上下文中的外部知识与参数中编码的知识生成回复。系统还可以额外设计证据核验、引用检查等步骤。

## 5. 评价知识增强系统

只看最终回答准确率，无法知道问题出在没检到、没读懂还是误生成。

| 层次 | 主要问题 | 示例指标 |
|---|---|---|
| 抽取 | 实体边界、关系和事件角色是否正确 | 实体/三元组/论元级 P、R、F1 |
| 检索 | 所需证据是否进入候选 | Recall@k、MRR、nDCG |
| 生成 | 回答是否正确、完整且符合要求 | 正确率、人工分维度评分 |
| 证据一致性 | 每个事实是否被引用材料支持 | 引用支持率、证据覆盖率 |
| 系统 | 是否在成本与延迟预算内完成 | 端到端延迟、调用数、成本 |

## 6. 大模型能力评测

本节按基础能力、应用能力和安全可靠性组织评价维度；这是一种划分方式，并非唯一标准。

基础能力包括阅读理解、生成、代码、逻辑、数学和长上下文。不同任务要有不同评分协议：代码需执行，数学需核验答案与必要过程，阅读理解需限定根据给定材料还是外部常识作答。

应用能力包括指令遵循、工具使用、角色扮演。工具评测不仅看有没有调用，还要看工具选型、参数、返回值理解、错误恢复和最终任务完成。输出 JSON 合法只是格式指标，不能替代任务正确率。

安全可靠性要分开看事实准确、一致性、偏见、隐私和抗攻击表现。
