# 11 提示工程与推理提示

## 1. 离散提示与连续提示

| 方法   | 被优化的对象      | 是否改模型参数          | 典型形式       |
| ---- | ----------- | ---------------- | ---------- |
| 离散提示 | 可读的词语、模板与示例 | 通常不改             | “请按表格列出依据” |
| 连续提示 | 可训练的向量表示    | 通常冻结主体模型，但训练提示向量 | P-Tuning 等 |

## 2. 提示自动优化：APO 与 APE

### 2.1 APO

流程：
1. 用当前提示运行任务，得到预测。
2. 将预测与目标答案一起交给大语言模型，分析错误原因。
3. 把错误分析视作梯度信息，将差异原因与初始提示通过一个模板再次送入大模型，由模型本身生成优化后的新提示。
4. 用新提示再次测试，保留效果较好的版本。

### 2.2 APE
考虑到复杂空间中初始值对于优化结果的影响，APE（Automatic Prompt Engineer）先从任务的输入输出示例生成多个候选指令，再在样本上评分，选出较好的候选，并以这些候选为基础再采样。它减少了对单一人工初始提示的依赖。

## 3. 思维链

思维链（Chain of Thought）提示通过带中间步骤的示例，或要求逐步推理的指令，引导模型在给出答案前生成中间推理步骤。
### 3.1 少样本与零样本 CoT

- **少样本 CoT**：给出若干带步骤的示例，适合任务过程较稳定、能写出正确示范的情况；示例质量和成本是限制。
- **零样本 CoT**：不给带步骤的样例，而用“请一步一步思考”等指令引导模型自行展开；节省人工示例，但中间步骤可能错误。

### 3.2 Auto-CoT

零样本思维链提示的主要问题在于， 大语言模型自动生成的分解步骤可能存在错误，而Auto-CoT 通过选择具有多样性的问题构造示例，减轻自动生成的错误推理链对最终回答的影响。

- Auto CoT首先会在一个问题库中将所有问题进行聚类，将问题嵌入聚为 K 类；在每类中按距聚类中心由近到远的顺序，选择一个满足启发式筛选条件的问题及其零样本 CoT 解答。将这些“问题—推理链—答案”组合为示例，用于回答待解问题。
### 3.3 自一致性思维链

自一致性（Self-Consistency）对同一问题采样多条推理路径，再汇总最终答案；常见做法是多数投票。设第 $j$ 条路径给出的最终答案为 $a_j$，则可写作：

$$
\hat a=\arg\max_a\sum_{j=1}^{m}\mathbf 1[a_j=a].
$$

## 4. 思维树与思维图：从单一路径到结构化搜索

思维树（Tree of Thoughts，ToT）在每个状态生成多个候选下一步，对候选评估，继续扩展有希望的分支并剪去低质量路径。它与单一路径 CoT 的关键差别是保留并比较多个候选，而非一开始就只沿一条路径走。搜索可采用广度优先或深度优先等策略。

思维图（Graph of Thoughts，GoT）允许多个步骤汇合，也允许返回已有节点继续改进；它强调推理结果的合并与复用，结构不再限于树。

| 结构 | 中间结果的组织 | 主要代价 |
|---|---|---|
| CoT | 一条线性步骤序列 | 走错后不易回溯 |
| ToT | 分支、评估、剪枝 | 额外候选生成与评价 |
| GoT | 分支、汇合、可能的循环 | 状态与依赖关系更复杂 |

# 12 检索增强生成 RAG

## 1. 检索增强概述

### 1.1 参数中的知识有时间和覆盖范围

训练结束后，模型参数不会随世界变化自动更新。问题可能涉及相对稳定的事实、缓慢变化的资料、快速变化的事件，甚至包含错误前提。对最后一种问题，系统首先要核查前提，而不是顺着问题编造答案。只靠参数生成的回答，也通常缺少可直接追溯的原始资料。

### 1.2 RAG 做了什么

检索增强生成（Retrieval-Augmented Generation，RAG）让生成模型在回答时参考检索到的外部资料。讲义给出的基本过程是：收集并组织资料、建立索引、根据问题检索相关内容、把内容与问题一起交给生成模型。

~~~text
离线准备：外部资料 → 解析和切分 → 建立索引
在线回答：用户问题 → 检索相关资料 → 构建提示 → 模型生成答案
~~~

### 1.3 优势

灵活性：便于更新外部知识；
安全性：可结合私有部署与权限控制管理资料访问；
可追溯性：可提供支持回答的原文与来源。
## 2. RAG 系统架构

### 2.1 朴素 RAG：建立索引—检索—生成

**第一步：建立索引。** 外部数据库中的数据往往以多种格式（PDF, doc, Markdown， HTML， Json等）存储，而常见的基于稠密向量检索的文本 RAG 要求使用纯文本构建数据库。因此构建索引的第一步是对原始数据进行文本提取，将其转换为纯文本格式。为了适应语言模型的上下文限制，处理过的文本会被分割成更小的文本块。最后，使用嵌入模型将文本块编码为向量表示，存储在向量数据库中用于后续的检索。

**第二步：检索。** 收到问题后，用与建库阶段相匹配的编码方法表示查询，计算它与各文本块的相关程度，选出得分较高的若干块。

**第三步：生成。** 把原问题和检索结果组成提示，让模型结合参考文本回答。

~~~text
文档 → 文本块 → 向量索引
问题 → 查询向量 → 取相关文本块 → 问题与文本块一起输入模型 → 回答
~~~

朴素 RAG 的局限来自每一环：分块可能切断条件，单次原始查询可能漏掉关键资料，召回结果可能重复或不相关，生成器即使拿到相关文本仍可能写出不受支持的结论。

### 2.2 高级 RAG：在检索前后改善输入质量

高级 RAG 保留“索引—检索—生成”的主链路，在检索**前**和检索**后**加入优化。它要解决的问题，正对应朴素 RAG 的索引粗糙、查询不清楚和召回噪声。

**预检索优化**发生在资料入库或正式检索之前：

1. 给文档补充标题、日期、部门等元数据，使系统知道文本属于什么资料；
2. 设计更合适的切块粒度与层次索引，必要时用小块定位、较完整的父段落提供上下文；
3. 对用户问题扩写、改写或路由，使检索查询更接近实际信息需求。

**后检索优化**处理已经召回的候选内容：

1. 重排序，把更能回答问题的片段排在前面；
2. 去重、筛掉无关内容，必要时压缩上下文；
3. 将保留下来的片段组织成生成提示。
### 2.3 模块化 RAG：按任务组合能力

模块化 RAG 不再要求所有问题走同一条固定路径。它把检索与生成拆成可替换的模块，按任务组合，并支持不同运行模式。

代表模块包括：

- **搜索模块**：可访问搜索引擎、知识图谱或数据库；有时让模型生成 SQL 等查询语句，再到相应数据源执行。
- **路由模块**：判断问题应进入哪个知识源或哪条检索路径。
- **融合模块**：生成多个相关查询，汇合各路检索结果；复杂问题可能需要来自不同资料的互补证据。
- **记忆模块**：保留原问题、已得结果等跨轮信息，供后续检索使用。
- **预测模块**：由模型生成可能有用的上下文内容。
- **任务适配器模块**：按下游任务选择或训练适合的检索器。

## 3. RAG 核心技术：资料、查询与回答

### 3.1 索引：数据从哪里来，切成多大

数据源包括在线文档与数据库、实时网页、企业内部资料、医疗等专业数据库以及 API等。不同来源的更新频率、格式与权限不同；在索引中保留来源、章节和时间，后续才可能判断哪条资料适用。

检索粒度是被检索单元的大小。粗粒度块保留更多语境，但无关信息也多；细粒度块便于定位，却可能把“金额”与“适用条件”分开。固定 token 长度、滑动窗口、父子结构或层次索引，都是可以选择的设计方向。

编码方式也影响“相关”的含义。TF-IDF、BM25 等稀疏方法重视词项；稠密嵌入更偏向语义相似。若问题含制度编号、罕见名称，词项信号很有用；若问法与文档措辞不同，语义信号可能补上词面差距。

### 3.2 检索：从原始问题到相关片段

- **查询扩写**：把一个查询扩成多种问法，或将复杂问题拆成子查询；目的是增加覆盖面。
- **查询转换**：把含指代、口语或不精确措辞的原问题改成适配资料的查询。
- **查询路由**：根据问题与元数据选择合适的索引区域、知识库或检索工具。

扩写后要合并与去重，子查询的答案要重新对齐原始问题。

规模较大时，向量索引常采用近似最近邻（ANN）搜索，以一定精度代价换取速度。ANN 解决“怎样快速找近邻”；稀疏/稠密编码解决“怎样表示和评分文本”，两者处于不同层次。专业领域还可用领域数据微调嵌入模型。
### 3.3 生成：把召回结果变成有依据的回答

召回只是得到候选片段。提示构建前，需要按相关性与支持程度重排序、去重，并在上下文太长时压缩。

重排序根据查询与候选片段的相关性重新排序，并可结合截断、过滤和去重控制上下文。在部分长上下文任务中，模型对中间位置的信息利用较差，因此可以尝试调整关键片段的位置；实际效果取决于模型与任务。

同时还可以通过微调来为生成器注入相应的领域知识。微调还可以调整模型的输入与输出格式，使大语言模型适应特定的数据格式，并按照指令生成特定样式的响应。

## 4. 进阶 RAG 技术

### 4.1 元数据、混合检索与图结构

**元数据**是与文本块一起保存的非向量信息，如日期、标题、章节、来源或权限。查邮件时，语义相似度无法直接表达“最近一周”；日期元数据可以参与过滤或排序。对有新旧版本的制度，也必须考虑生效时间。

**混合检索**结合稀疏和稠密检索，利用词项精确匹配与语义匹配的互补性。可以一类方法先召回候选，另一类方法补充或重排；具体顺序取决于系统设计。

**图结构检索**把实体及其关系组织成图，沿关系路径寻找分散在多处的资料。它适合涉及多跳关联的问题，但图中边的来源及其对应原文仍需保留，避免只凭关系路径生成未经核查的结论。

### 4.2 迭代、递归与自适应

一次检索不足以回答复杂问题时，下面介绍三种增强策略：

- **迭代式 RAG**：根据初始查询和已生成内容继续检索，逐轮积累资料；同时可能积累噪声。
- **递归式 RAG**：不断分解或重写原问题，深入查询更细的子问题。
- **自适应 RAG**：依据当前问题和中间结果决定是否检索、怎样筛选资料。

迭代式与递归式策略通常通过多轮检索逐步补充证据；自适应策略则按需决定是否检索、何时检索，以及是否继续检索。

## 5. 多模态 RAG

### 5.2 怎样表示、检索和生成

一种路线把资料转成文本：OCR 提取图片文字，语音转写音频，图像描述或字幕概括画面。另一种路线用相应编码器建立图像、音频、视频表示，进行同模态或跨模态检索；两种线索也可结合。

检索到的素材可用于回答“图中有什么”“这段视频先发生什么”，也可作为图像或视频生成的参考。组合输出时，文字与插入素材应对应，而不是仅在答案后附一张相关图。
